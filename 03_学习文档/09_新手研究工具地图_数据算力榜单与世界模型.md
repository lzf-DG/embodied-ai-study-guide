# 新手研究工具地图：数据、算力、榜单与世界模型

补充于 2026-10-23。目标是读懂论文与项目介绍，知道实现一个功能需要哪些内容。本文的工程配置、计算和杯子例子是教学说明，不是已经运行的实验。项目接口、榜单规则和硬件支持会变化，实际使用时核对链接中的官方文档。

推荐把这一章插在仓库入门导读之后，再读五篇论文。第一次先看第 1、2、4、7 节；需要选数据或做实验时查第 3、5、6、8 节。不要一次记住全部名字。

## 1. 先分清研究中六种不同的“东西”

| 名称 | 提供什么 | 收拾杯子的例子 |
|---|---|---|
| Dataset，数据集 | 已记录的图像、动作、状态等资料 | 人演示如何抓杯子的轨迹 |
| Simulator，仿真器 | 根据动作计算世界变化，产生观测 | 夹爪合拢后，模拟杯子受力与移动 |
| Environment / Task Suite，环境 / 任务套件 | 在仿真器上定义机器人、场景、目标、重置和接口 | 不同位置、形状和遮挡的抓杯子任务 |
| Benchmark，评测基准 | 任务、数据划分、成功标准、预算等比较规则 | 在未见杯子与固定试验次数下比较成功率 |
| Leaderboard，榜单 | 在特定规则下展示提交成绩 | 某个模型在该任务集合中的分数 |
| Model / Checkpoint，模型 / 权重检查点 | 网络结构及训练得到的参数 | 根据图像生成抓取动作的已训练策略 |

一个项目可以同时提供多种东西：RoboTwin 提供任务、数据生成与评测；LIBERO 提供终身机器人学习任务和演示；LeRobot 提供数据格式、训练和硬件接入工具。看到一个名称，先查它属于哪些层，而不是一概叫“数据集”。

Dataset 是静态经验，Environment 能继续交互。训练算法是学习方法，Checkpoint 是某次训练的结果。训练完成不等于有了可部署系统，还需要相机、动作接口、归一化和控制器。

本文会用到 AI（Artificial Intelligence，人工智能）、IL（Imitation Learning，模仿学习）、RL（Reinforcement Learning，强化学习）、VLA（Vision-Language-Action，视觉语言动作模型）与 ACT（Action Chunking with Transformers，用 Transformer 进行动作分块）。IL / RL 是学习方法，VLA 描述连接的模态与能力，ACT 是一种具体策略方法；它们不属于同一层。其余缩写在相关段落给出全称，原学习包的 08 术语表也可随时查阅。

## 2. 一条数据怎样变成模型输入

### 2.1 新手会频繁看到的字段

| 字段 | 含义 | 需要核对什么 |
|---|---|---|
| Episode / Trajectory | 一次完整任务 / 时间轨迹 | 起止边界、成功或失败、是否可恢复 |
| Step / Timestep | 一个记录时刻 | 时间戳、采样频率、是否有丢帧 |
| Observation | 模型可获得的观测 | 哪些相机、身体状态和历史信息 |
| Action | 发给机器人的指令 | 关节或末端、绝对或增量、位置或速度、单位 |
| State | 任务相关状态变量 | 实际传感器能获得，还是仿真特权信息？ |
| Reward | 强化学习的反馈分数 | 与真正完成任务是否一致？ |
| Done / Termination / Truncation | 结束 / 任务终止 / 截断 | 成功、失败、超时和预算结束应区分 |
| Language Instruction | 语言任务说明 | 对应整段轨迹还是某个子任务？ |
| Metadata | 来源、本体、相机、标定与版本等信息 | 能否解释不同样本的接口和采集条件？ |

RGB（Red, Green, Blue，红绿蓝图像）提供外观；RGB-D（RGB plus Depth，彩色加深度）增加空间距离；点云是三维点集合；Proprioception（本体感知）描述身体的关节、速度等状态。它们提供互补信息。

教学形状例子：两路相机、三帧历史、每张 224×224 像素，可形成 `[批量, 时间, 相机, 通道, 高, 宽]` 的输入。实际顺序以代码为准。动作块可能是 `[批量, 未来步数, 动作维数]`。同样是 7 维，也可能分别代表不同机械臂关节，或末端位移、旋转和夹爪，不能只看数组长度猜含义。

### 2.2 常见数据格式与工具

RLDS（Reinforcement Learning Datasets）是存取与处理序列决策数据的格式和工具生态，强调 Episode / Step 结构。Open X-Embodiment 使用它组织不同来源经验。TFDS（TensorFlow Datasets）是数据加载与管理工具，不是一份机器人数据集。

HDF5（Hierarchical Data Format version 5）可以在一个文件中组织图像、动作与元数据。LeRobot Dataset 是 LeRobot 定义并随版本发展的机器人数据组织方式，结合结构化记录、视频和元数据。Parquet 是列式存储格式，MP4（MPEG-4 Part 14；MPEG 为 Moving Picture Experts Group，动态图像专家组）是常见视频容器；它们不是学习算法。

统一文件格式不意味着统一动作语义。两个数据集都能被同一个加载器读取，一个是米，一个是毫米，模型仍会学错。要检查图像解码、颜色顺序、时间同步、相机标定、动作单位与统计归一化。仓库对特定图像解码工具的提醒正是在解决这类问题。

### 2.3 数据划分比“下载多少”更重要

Train / Validation / Test（训练 / 验证 / 测试）承担不同用途。训练集用于更新参数，验证集用于选择超参数和版本，测试集用于最后的独立检验。如果持续按测试结果补数据，测试集就逐渐成为开发工具。

按帧随机划分，会把同一轨迹的相邻帧分到训练和测试；按轨迹划分，仍可能共享同一物体和背景；按对象、场景、任务或本体划分，考察的泛化更不同。论文中的 Unseen（未见）必须问“到底未见什么”。

## 3. 常见数据与环境：按用途识别

专有项目名不一定是缩写。下面给出官方名称或论文题目；没有可确认的字母展开时，保留名称并解释用途，不强行编造全称。数字规模不作为长期固定标准，下载前查当前版本。

### 3.1 真实机器人操作数据

| BridgeData V2；论文 A Dataset for Robot Learning at Scale | 多环境操作行为，包含语言说明和演示 | 语言条件策略、跨场景迁移 |

### 3.2 仿真操作任务与配套演示

| 项目 | 主要侧重 | 新手应注意 |

| RoboTwin | 双臂操作、自动数据生成与统一评测 | Clean 与 Randomized 条件、相同任务的不同测试分布 |

| CALVIN；A Benchmark for Language-Conditioned Policy Learning for Long-Horizon Robot Manipulation Tasks | 语言条件下的多步骤连续操作 | 常见指标是连续完成链长，不应与单步成功率混用 |
| RLBench：Robot Learning Benchmark | 视觉引导操作、任务变化与演示生成 | 依赖 CoppeliaSim；任务和相机设置会影响结果 |
| ManiSkill | 操作环境、机器人、演示与训练基线 | 依赖 SAPIEN；适合研究仿真采样和操作学习 |

LIBERO 名称保留原名，解释使用官方论文标题，不将名称字母强行展开。论文里经常出现 LIBERO-10，它通常对应从 LIBERO-100 划出的较长任务集合；下载与比较时查看具体 split（划分），不能用“10”猜所有任务难度。

CALVIN 的 LH-MTLC 全称是 Long-Horizon Multi-Task Language Control，意为长时程多任务语言控制。它要求按连续语言指令推进任务，前面失败会影响后面。不是简单把多个独立任务成功率平均。

官方入口：[RoboTwin](https://robotwin-platform.github.io/doc/)、[LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)、[CALVIN](https://github.com/mees/calvin)、[RLBench](https://github.com/stepjam/RLBench)、[ManiSkill](https://maniskill.readthedocs.io/)、[Meta-World](https://meta-world.github.io/)、[BEHAVIOR](https://behavior.stanford.edu/)。

### 3.3 导航、视频与驾驶数据：为什么也会出现在世界模型论文里

Habitat 是具身导航和交互的模拟平台；HM3D（Habitat-Matterport 3D）与 Matterport3D 提供室内三维场景，主要帮助构建环境，不自动带有与某种机械臂一致的抓取动作标签。ObjectNav（Object-Goal Navigation）找指定类别物体；PointNav（Point-Goal Navigation）走到指定目标位置；VLN（Vision-and-Language Navigation）根据视觉与语言指令导航。

DMC（DeepMind Control Suite）提供物理控制任务，是研究潜空间世界模型与基于模型的强化学习的常见入口。Atari 游戏环境也常见于这类研究，但游戏表现不直接说明真实机械臂操作能力。

SSv2（Something-Something V2）等人类视频数据可帮助学习物体变化与视觉表征，但通常缺少对目标机器人可直接执行的动作。Waymo Open Dataset 的驾驶数据包含不同子集与任务，适合研究动态场景、感知或轨迹预测；它不是机器人操作数据的直接替代品。

官方入口：[Habitat](https://aihabitat.org/)、[HM3D](https://aihabitat.org/datasets/hm3d/)、[DeepMind Control Suite](https://github.com/google-deepmind/dm_control)、[Waymo Open Dataset](https://waymo.com/open/)。

### 3.4 如何选第一份数据

先按功能选：学 BC（Behavior Cloning，行为克隆）需要观测和专家动作；学动作条件世界模型需要连续观测和对齐动作；做导航需要环境、移动动作与目标；做记忆 / 恢复需要含失败或多步骤状态的任务。

再核对本体、动作、相机、语言、是否含失败、下载量、许可和基线。当前理解阶段只需看少量样本与字段说明。不要为认识一个数据集而下载整个超大集合。

## 4. 算力到底是什么：不要只数显卡

### 4.1 六种资源瓶颈

CPU（Central Processing Unit，中央处理器）负责数据解码、调度、部分物理计算和环境逻辑。GPU（Graphics Processing Unit，图形处理器）适合神经网络并行计算、渲染和部分并行物理。RAM（Random Access Memory，系统内存）存放程序和主机数据；显存是加速器保存模型、激活和设备数据的内存，不能与普通内存直接互换。

VRAM（Video Random Access Memory）常被泛指显卡显存；HBM（High Bandwidth Memory，高带宽内存）是部分加速器使用的实际内存技术。Unified Memory（统一内存）让部分设备共享物理内存，但框架支持、带宽与可用量仍决定实际表现。

存储容量决定数据是否放得下；SSD（Solid-State Drive，固态硬盘）的读写速度影响加载。网络带宽影响下载和多机通信。Memory Bandwidth（内存带宽）决定设备传输数据速度，TFLOPS 再高也可能被数据访问拖慢。

FLOP（Floating-Point Operation，浮点运算）是运算量单位；FLOPS（Floating-Point Operations Per Second）是每秒速度；TFLOPS（Tera Floating-Point Operations Per Second）是每秒万亿次浮点运算。比较数字时要对齐 FP32、FP16、BF16 等精度与是否使用稀疏计算；厂商理论峰值不等于训练实测吞吐。

### 4.2 显存分给了谁

推理需要权重、输入、激活和缓存；自回归 Transformer 还常用 KV Cache（Key-Value Cache，键值缓存）。训练额外保存梯度、优化器状态与反向传播所需的中间结果。仿真环境和相机渲染也可能占同一张显卡。

教学计算：B 为 Billion，1B 表示约十亿参数。若每个参数用 16 位，即 2 字节，权重本身约 2 GB；7B 权重约 14 GB。GB（Gigabyte）等于十亿字节，GiB（Gibibyte）等于 2 的 30 次方字节。这只是参数存储，不是完整运行显存。

Adam（名称源自 Adaptive Moment Estimation，自适应矩估计）是一种常见优化器。一个混合精度 Adam 训练配置可能需要约 16 字节 / 参数，包括低精度权重、主权重副本、梯度和两个矩估计状态；因此 1B 参数仅相关状态就可能约 16 GB，还没算激活。不同实现的状态精度和分片方式不同，这个例子不能当作统一公式。

图像更多、分辨率更高、历史更长、动作块更长或 batch 更大，都可能增加成本。视频世界模型的时间和空间开销尤其明显。OOM（Out Of Memory，内存不足）不只可能是显存不足，也可能来自主机内存，先看错误位置。

### 4.3 精度与省显存方法

| 名称与全称 | 用途 | 不要误解成什么 |
|---|---|---|
| FP32：32-bit Floating Point | 常规单精度计算 | 不是所有模块都必须采用它 |
| FP16：16-bit Floating Point | 减少部分计算和存储成本 | 可能需要处理数值稳定性 |
| BF16：Brain Floating Point 16 | 另一种 16 位浮点格式，指数范围较大 | 与 FP16 有不同数值特征，硬件支持需核对 |
| AMP：Automatic Mixed Precision | 自动组合不同精度 | 不会消除全部训练内存 |
| LoRA：Low-Rank Adaptation | 用低秩增量做参数高效微调 | 基础模型仍要加载，激活仍占内存 |
| PEFT：Parameter-Efficient Fine-Tuning | 参数高效微调方法总称 | 不等于只有 LoRA 一种方法 |
| Quantization，量化 | 用较低位宽表示部分数值 | 推理适用不代表直接适合所有训练和控制模块 |
| Gradient Accumulation，梯度累积 | 多个小批量累计后更新 | 能减少单次批量占用，通常增加运行时间 |
| Gradient Checkpointing，梯度检查点 | 少存激活，在反向时重算 | 用更多计算换显存，不是断点权重文件 |

### 4.4 单卡、多卡与部署频率

DDP（Distributed Data Parallel，分布式数据并行）通常让各卡保存完整模型副本，各处理不同样本。因此两张 24 GB 卡不自动成为一张 48 GB 卡。FSDP（Fully Sharded Data Parallel，全分片数据并行）等方法可分片参数、梯度和状态，但需要额外通信与正确配置。

吞吐 Throughput 表示每秒样本、帧或 token 数；延迟 Latency 表示一次请求需要多久。机器人关心动作是否及时返回：批量推理吞吐很高，也可能单次动作延迟太大。Hz（Hertz，赫兹）表示每秒次数，30 FPS（Frames Per Second）图像与 100 Hz 控制不必一一对应，时间同步与延迟补偿需要专门设计。

### 4.5 当前学习阶段需要多少

| 阶段 | 合理起点 | 主要限制 |
|---|---|---|
| 阅读、看样本、理解数据字段 | 普通电脑即可，数据按需取样 | 大视频解码和数据下载仍可能慢 |
| 一个任务的小型 ACT / Diffusion Policy 基线 | 单张约 16-24 GB 显存的支持设备可作为规划起点 | 配置、图像、批量和仿真决定实际需求 |
| 冻结特征编码器、小世界模型实验 | 先降低图像大小、预测长度和批量 | 不能由参数数目单独估算成本 |
| 大 VLA 微调或高分辨率视频模型 | 按模型官方配方选 40-80 GB 级或多卡资源 | PEFT 能降低部分需求，不能保证消费卡都可跑 |
| 从零训练大规模视频世界模型 | 通常是数据、集群和系统工程项目 | 不适合作为当前入门的第一步 |

这些是选择实验规模的粗略参考，不是保证配置。租服务器前先做最小批量试跑，测峰值显存、每轮耗时、存储占用和真实任务效果；不要仅凭论文用了哪张卡就照抄。

### 4.6 论文里的加速器型号与集群词汇

GeForce RTX 系列是常见消费级显卡产品，例如 RTX 3090 / 4090 的常见配置为 24 GB 显存。这里将 RTX 保留为产品品牌，不编造算法全称。A100、H100、H200 是 NVIDIA 数据中心加速器型号；同一型号也可能有不同显存与设备形态。不能只凭“用了 H100”就推断论文训练成本或你的复现配置。

TPU（Tensor Processing Unit，张量处理单元）是 Google 的专用加速器；NPU（Neural Processing Unit，神经网络处理单元）是更一般的专用加速器类别。AMD GPU、TPU、Apple 加速器都需要对应软件支持，不是所有 CUDA 项目都能直接迁移。当前阶段无需为了阅读论文购买设备。

Node（计算节点）通常指一台服务器，Cluster（集群）是多节点系统。GPU-Hour（GPU 小时）约等于设备数乘运行小时；8 张卡运行 10 小时是 80 GPU 小时，但不同型号、利用率与任务的这项数字不能直接比较。租用成本还包括存储、下载和空闲时间，应先看实际计费规则。

PCIe（Peripheral Component Interconnect Express）连接设备与主机；NVLink 是 NVIDIA 的高速设备互联技术；InfiniBand 是常见集群互联技术。它们影响多卡 / 多机通信，拥有更多卡不保证按卡数等比例加速。Slurm（原名源自 Simple Linux Utility for Resource Management）是常见集群作业调度系统：提交任务、申请卡和内存、排队与查看日志，也是实验室研究基础设施的一部分。

## 5. 基础设施：实现功能需要的工具层

### 5.1 从底层到项目接口

操作系统和驱动支撑硬件；CUDA（Compute Unified Device Architecture）是 NVIDIA 的并行计算平台；PyTorch / JAX 等框架实现模型和训练；数据管线读入轨迹；仿真器处理物理和渲染；任务套件定义目标；训练与评测程序将这些部分连接起来。

Python 虚拟环境用于隔离依赖；Docker 是容器工具，便于打包软件环境，但不能抹去 GPU 驱动、架构和渲染支持差异。Checkpoint、配置、代码版本和数据版本共同决定能否复现。

macOS 可以用于阅读、数据处理与部分小模型。MPS（Metal Performance Shaders）提供 Apple 平台上的部分加速能力，但支持它不等于支持依赖 CUDA 的机器人项目。机器人训练与仿真仓库常围绕 Linux 与 NVIDIA 测试，安装前查各项目支持矩阵。

### 5.2 常见平台怎么分工

| 名称 | 主要角色 | 应连接到哪个问题 |
|---|---|---|
| MuJoCo：Multi-Joint dynamics with Contact | 接触动力学仿真引擎 | 物理是否正确、如何执行控制量 |
| SAPIEN | 物理与视觉模拟平台 | 操作场景、相机与交互；不是策略模型 |
| Isaac Sim / Isaac Lab | 仿真系统 / 机器人学习与任务框架 | 场景传感器、并行训练与执行接口 |
| CoppeliaSim | 机器人仿真平台 | RLBench 等任务的底层环境 |
| PyBullet | Bullet 物理的 Python 接口与环境工具 | CALVIN 等项目的仿真基础 |
| Gymnasium | 强化学习环境接口标准与工具 | reset / step / observation / action 的调用约定 |
| robomimic / LeRobot | 数据、策略训练与评测工具 | 从演示到训练、部署与记录 |
| ROS 2：Robot Operating System 2 | 机器人消息、中间件与工具生态 | 相机、机器人状态、控制模块之间如何通信 |
| MoveIt 2 | 运动规划与机器人操作工具 | 目标位姿怎样转换为无碰撞路径 |

MuJoCo 原生引擎、其 GPU 后端与上层任务套件的能力不同，不能只看到项目用 MuJoCo 就判断是否所有物理都跑在 GPU。Isaac Sim 和 Isaac Lab 也不是同一个层：后者围绕机器人学习组织任务与训练。

URDF（Unified Robot Description Format）描述机器人关节、连杆等结构；MJCF（MuJoCo XML Format）是 MuJoCo 的模型描述格式，XML 为 Extensible Markup Language。这类文件告诉模拟器机器人是什么，不会自动训练出策略。

### 5.3 容易被模型图省略的内容

相机内外参、手眼标定、时钟同步、控制频率、动作限制、碰撞检测、任务重置、数据日志、成功检测、异常处理都属于系统。模型预测一个末端位姿，还需要 IK（Inverse Kinematics，逆运动学）、运动规划和控制器将其变成可执行运动。

云 GPU 或实验室服务器只提供部分计算资源，不一定提供机器人仿真可用的渲染环境。无显示器运行叫 Headless，不等于不渲染；如果策略吃图像，仍然需要生成相机图像，并核对渲染库和驱动。

工程实用工具还包括 Git 版本管理、实验配置、日志与指标记录、任务种子 Seed、断点续训和缓存。固定 Seed 有助于比较，却不保证不同硬件或软件版本结果完全相同。

官方文档：[MuJoCo](https://mujoco.readthedocs.io/en/stable/overview.html)、[Isaac Lab](https://isaac-sim.github.io/IsaacLab/main/index.html)、[ROS 2](https://docs.ros.org/)、[RLDS](https://github.com/google-research/rlds)、[LeRobot](https://huggingface.co/docs/lerobot/en/index)。

## 6. 榜单、打榜网站与论文检索怎么用

### 6.1 推荐关注的官方入口

| 网站 / 项目 | 看什么 | 怎样使用 |
|---|---|---|
| [RoboTwin Leaderboard](https://robotwin-platform.github.io/leaderboard) | 双臂操作的任务结果与条件 | 先读 Setting 和提交规则，再看模型排名 |
| [RoboDojo](https://robodojo-benchmark.com/) | 仿真与真机的操作评测、能力维度 | 区分 Sim / Real、本体、Score 和成功率 |
| [LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO) | 任务划分、演示、基线和评价代码 | 常在论文 / 仓库对照表比较，不必有统一在线提交榜 |
| [CALVIN](https://github.com/mees/calvin) | 长时程语言操作协议与连续任务指标 | 查看链长和环境划分，不与普通成功率混排 |
| [Habitat Challenge](https://aihabitat.org/challenge/) | 具身导航与相关挑战 | 按年份确认赛道、数据与提交入口 |
| [BEHAVIOR Challenge](https://behavior.stanford.edu/) | 家庭活动任务、基线、规则与榜单 | 关注完整任务和实际评测赛道 |
| [Waymo Open Dataset Challenges](https://waymo.com/open/) | 感知、运动预测等不同驾驶赛道 | 只与相同赛道和版本的方法比较 |
| [Hugging Face](https://huggingface.co/) | 权重、数据、模型卡和演示 | 下载与复现入口；受欢迎程度不是任务能力排名 |

有的基准提供评测代码和论文结果，没有持续维护的公开榜单；有的榜单需要提交容器或权重，由服务器评测；也有作者自行报告的结果。先查证据来源，再解释排名。

arXiv 是预印本平台，GitHub 是代码托管与协作平台，OpenReview 用于部分会议投稿和评审，Google Scholar、Semantic Scholar 可帮助检索文献。这些都不是机器人能力统一榜。论文名、引用数和仓库星数适合发现资料，不能代替实验质量判断。

### 6.2 打榜之前必看的问题

问清任务、训练数据、测试划分、动作接口、观测权限、模型版本、随机种子与试验次数；还要看每次能重试几次、能用多少计算、是否允许测试时训练、是否有人干预。榜单日期也应记录。

Zero-Shot（零样本）通常表示没有针对目标设置作额外训练，但模型仍可能经过其他训练；Few-Shot（少样本）使用少量目标经验；Fine-Tuning（微调）更新已有模型。定义与预训练重叠情况必须看具体协议。

SR（Success Rate，成功率）不是所有榜单的 Score。Score 可能综合不同维度。导航还常使用 SPL（Success weighted by Path Length，按路径长度加权的成功指标），奖励成功且路径高效的行为。CALVIN 连续链长则考察多任务串联可靠性。

教学例子：模型 A 的 SR 为 80%，来自 20 次简单场景试验；模型 B 为 75%，来自 500 次带遮挡试验。不能据此说 A 更强。即使设置相同，试验次数、方差与置信区间也影响结论。

Ablation（消融）问“去掉这个模块会怎样”；Baseline（基线）是参照方法；SOTA（State of the Art）表示作者在指定设置中相对先进的结果，必须附具体基准与条件。OOD（Out Of Distribution，分布外）强调与训练分布不同，不能只用“没见过”三个字带过。

## 7. 世界模型：实现预测与规划需要哪些板块

### 7.1 一张完整的功能图

![图12 世界模型与动作选择](图解/12_世界模型用途.png)

读图：左侧学习世界如何变化，右侧选择如何使用预测。规划器可在线搜索；策略也可先在想象轨迹中训练。更详细的先验、后验与训练目标见 10 算法详解第 11 节。

```text
真实 / 仿真交互轨迹
    → 数据整理、时间同步、动作定义与划分
    → 观测编码器：把图像、身体状态等变成表征
    → 状态 / 历史模块：整合当前与过去的信息
    + 候选动作、目标及其他条件
    → 动态预测器：预测状态如何演变
    → 按用途输出特征、图像、几何、奖励或终止信息
    → 规划 / 策略学习：利用预测选择动作
    → 控制与环境执行
    → 新观测校正、记录误差、继续预测与评测
```

这个图是功能清单，不要求每个框必须是独立网络。一个 Transformer 可以承担多个功能。世界模型本身可以只做预测；当目标是机器人规划或控制时，还要补上动作选择和执行闭环。

### 7.2 数据板块：模型得见过怎样的变化

预测下一帧需要连续观测；预测“执行动作后怎样”还需要时间对齐的动作。图像帧、指令时间与实际执行结果错位，模型就会学错因果关联。还要明确状态、相机、采样频率和动作单位。

仅有专家成功演示，可能缺少滑落、抓空与危险动作的后果。仅有人类视频，又缺少机器人可执行动作。不同来源能补充不同能力，不能把所有视频直接当成控制训练数据。

### 7.3 表征板块：预测什么东西

Encoder（编码器）把观测转换为有用表征。可以用紧凑潜向量、图像 patch token（局部图像词元）、空间网格、点云、对象表示或可渲染几何。选择依据是预测用途、空间精度和计算预算。

Latent Space（潜空间）是压缩表示的空间，不是另一份物理世界。预测潜特征可以省去生成纹理，但特征要保留接触、位置或其他任务需要的信息。全部特征预测得很准，也不一定保证遗漏的物理量正确。

### 7.4 状态与记忆板块：遮住杯子后它还在吗

单帧看不到遮挡后的杯子，历史能够帮助推断位置和存在性。模型可以使用循环结构、注意力历史、RSSM（Recurrent State-Space Model，循环状态空间模型）或其他状态估计方式。

Belief State（信念状态）表达在部分观测下对可能世界状态的估计，可以包含不确定性。它不同于“确定记住一个位置”：若杯子可能被人挪动，状态需要允许不确定并寻求新观测。

### 7.5 条件与动态板块：动作如何改变未来

Action-Conditioned Dynamics（动作条件动态）将当前表征和动作映射为未来表征。语言、目标、相机位姿、本体信息也可作为条件，但这些条件不能与物理动作混淆。

教学对照：不含动作的模型问“接下来通常会发生什么”；含候选动作的模型问“如果夹爪向左移动并闭合，会发生什么”。后者才直接支持比较不同动作后果。部分方法从视频学习隐式动作或潜在动作，再映射到机器人动作；该映射的有效性仍需检查。

动态模型可以逐步自回归预测，也可以分块 / 联合预测多个未来时刻；可用确定性回归、概率状态模型、扩散、流匹配等方法。时间预测方式与空间表示是不同维度，不能把“扩散”简单等同于全部世界模型。

### 7.6 输出板块：按用途添加，不必全部都有

Decoder（解码器）把预测表征还原为图像或其他可读量。若规划直接比较预测特征与目标特征，图像解码器可以是可选项。Reward Head（奖励头）、Value Head（价值头）或 Termination Head（终止预测头）帮助判断任务价值与结束，适合某些强化学习方法，并非所有世界模型的必备结构。

几何输出用于碰撞与空间关系；图像输出便于可视化或训练下游视觉策略；对象状态便于检查是否抓住杯子。Inverse Dynamics Model（逆动态模型）从状态变化推断动作，是部分从未来计划到动作的方法使用的组件，不能仅凭预测视频就默认存在。

### 7.7 学习目标板块：用什么信号让模型变好

可以比较下一观测、特征或状态预测与真实结果，也可结合奖励、终止、几何和多步一致性目标。MSE（Mean Squared Error，均方误差）衡量回归差异；NLL（Negative Log-Likelihood，负对数似然）用于概率预测；KL Divergence（Kullback-Leibler Divergence，KL 散度）可约束概率分布。这些不是每个模型都必须同时包含的损失。

JEPA（Joint Embedding Predictive Architecture，联合嵌入预测架构）强调表征预测。V-JEPA（Video Joint Embedding Predictive Architecture，视频联合嵌入预测架构）属于视频表征路线。DINO（Self-Distillation with No Labels，无标签自蒸馏）可提供视觉特征；DINO-WM 利用预训练特征学习动态与规划，不表示 DINO 本身已经是动作条件世界模型。

需要防止表示坍缩：若模型对所有图像都输出相同特征，特征预测损失可能很低，却没有有用信息。还要区分训练时每步看真实状态与推理时连续使用自己预测的状态；后者更容易累积误差。

### 7.8 规划与控制板块：预测如何产生动作

Planning（规划）可以比较候选动作序列的预测结果，或在潜空间中优化动作。MPC（Model Predictive Control，模型预测控制）每次规划未来一段，执行第一步或一小段，再用新观测重规划。

另一条路线是 Model-Based Reinforcement Learning（基于模型的强化学习）：在想象轨迹上训练 Actor（动作策略）和 Critic（价值评价器），部署时用策略行动。Dreamer 系列是这类路线的重要代表。规划与想象训练能组合，但成本和误差传播不同。

```text
当前表征 = 编码(真实观测与必要历史)
产生若干候选动作序列
for 每个候选:
    用动作条件模型展开未来
    根据目标、风险与成本评分
执行最好序列的第一步
读取真实新观测，校正表征
再次规划
```

伪代码里的风险项不会自动获得安全保证。若世界模型对碰撞预测不准，规划器仍可能选出危险动作，需要另行检查实际约束和环境结果。

### 7.9 评测与不确定性板块：好看不等于可控

PSNR（Peak Signal-to-Noise Ratio，峰值信噪比）与 SSIM（Structural Similarity Index Measure，结构相似性指标）衡量部分图像差异；FVD（Fréchet Video Distance，弗雷歇视频距离）用于视频分布比较。它们不能独立证明接触、因果或控制能力。

同时看状态误差、动作敏感性、时间一致性、对象持续存在、物理约束、下游任务成功和推理延迟。换一个动作，预测是否产生合理不同结果，是很有用的检查。

Uncertainty（不确定性）可来自随机状态、多模型集合、概率输出或其他估计，但不等于有了可靠校准。Calibration（校准）要求预测信心与实际正确率有对应关系。误差大或分布外时，系统可以限制动作、获取新观测或使用其他可靠机制；具体需要验证。

## 8. 三种世界模型项目，需要的东西并不相同

| 目标 | 最小需要的内容 | 可以暂缓的内容 |
|---|---|---|
| 学会预测视频 / 特征 | 连续数据、编码 / 表征、预测器、学习目标与预测评测 | 机器人动作规划和真机部署 |
| 用模型规划抓杯子 | 对齐动作的轨迹、可用状态表征、动作条件动态、目标评分、规划器、执行反馈 | 大视频生成器；仅特征规划可不重建像素 |
| 在想象中学习动作策略 | 动态模型、奖励 / 价值等学习信号、想象轨迹、策略训练、环境验证 | 每一步都由大型规划器搜索 |

若当前要从理解走向最小实验，建议冻结一个现成视觉编码器，在一个仿真任务的小数据上学短期动作条件特征预测，再检验是否有利于选动作。先比较一步预测与多步展开、训练误差与独立任务成功，不要直接追求生成整段高分辨率世界。

没有动作对齐数据时，可以学习视频表征与预测，却不能因此宣称已学会可靠的机器人可控动态。没有执行接口和任务评分时，可以演示未来画面，却仍缺少完整的规划 / 控制系统。

方法入口：[DreamerV3](https://github.com/danijar/dreamerv3)、[DINO-WM](https://github.com/gaoyuezhou/dino_wm)、[V-JEPA 2](https://github.com/facebookresearch/vjepa2)。这些链接用于下一阶段理解代码，未要求现在安装所有项目。

## 9. 其他很常见的研究词汇

| 词汇与全称 | 一句话解释 | 杯子例子 |
|---|---|---|
| MDP：Markov Decision Process | 用状态、动作、转移和奖励描述决策 | 假设当前状态足以预测下一步 |
| POMDP：Partially Observable Markov Decision Process | 决策时只能获得部分观测 | 杯子被遮挡，需记忆与估计 |
| Open-Loop / Closed-Loop | 无中途反馈执行 / 持续依据反馈调整 | 按整段轨迹走 / 抓空后重定位 |
| Offline / Online Learning | 用已有资料学习 / 随交互产生新资料并学习 | 学演示 / 练习后更新策略 |
| On-Policy / Off-Policy | 用当前策略 / 其他策略产生的经验作学习依据 | 最新练习 / 旧演示；具体定义依算法 |
| Replay Buffer，经验回放池 | 保存交互供训练采样 | 成功和失败都可回放 |
| Curriculum Learning，课程学习 | 组织逐渐适配能力的训练任务 | 从无遮挡到复杂遮挡 |
| Test-Time Adaptation，测试时适应 | 测试执行阶段更新状态或模型以适应 | 必须在协议中说明允许更新什么 |
| Teacher Forcing，教师强制 | 训练时用真实历史作为输入 | 与推理时依赖自身预测不同 |
| Autoregressive，自回归 | 下一步依赖之前输出或状态 | 逐步生成未来表征 |
| Receding Horizon，滚动时域 | 执行一小段后重新规划 | 每次只执行计划的前部分 |
| Sim2Real / Real2Sim | 仿真到现实 / 真实场景重建到仿真 | 摩擦迁移 / 把桌面重建进模拟器 |
| Retargeting，动作重定向 | 把一种身体的运动映射到另一种本体 | 人手示范映射到机器人手 |
| Affordance，可供性 | 在特定身体条件下可能的交互 | 这个夹爪能否抓住杯柄？ |

Transformer 中的 Token 是模型处理的单位，可能是词、图像块、动作或状态，而不总是一个汉字。Embedding（嵌入）是把单位变成向量。Backbone（主干）提取主要表示，Head（预测头）输出指定量。Pretraining（预训练）、Fine-Tuning（微调）、Inference（推理）分别是广泛学习、针对性更新与使用模型，资源需求不同。

## 10. 一页研究系统检查表

看到新方法时先写：任务和本体；观测与动作；数据来源与划分；核心模块；训练目标；部署频率；成功判据；计算预算；失败模式；代码与权重是否能找到。

如果是世界模型，再问：预测对象是什么？有无真实动作条件？是否需要历史？误差怎样累积？规划依据什么评分？实际执行后是否重观测？预测收益是否超过时延与计算代价？

如果是榜单，再问：比较的是相同任务、观测、预算、数据和版本吗？有没有误用训练数据、只看成功演示或隐藏人工干预？有没有多个随机种子和误差报告？

如果要动手，先让一条样本从读取到执行完整通过。字段、单位、时间和接口都清楚之后，再决定换模型或扩大算力。

## 11. 自测：学会按问题选择内容

问题一：我想做动作条件世界模型，拿到很多人类视频就够了吗？不够。可先学视觉预测，但要支持机器人动作比较，还需合适动作表示、时间对齐和落地关联。

问题二：两张 24 GB 卡能直接运行需要 40 GB 单卡内存的模型吗？不能自动。数据并行通常每卡仍保留完整模型；分片需要明确的方案与支持。

问题三：LIBERO 的数字比另一个真机榜高，证明模型更强吗？不能。任务、本体、观测、预算和成功标准都可能不同。

问题四：世界模型必须生成视频、奖励和机器人动作吗？不必须。预测形式依用途选择；若目标是完整控制，需要另外提供动作选择、执行和反馈。

问题五：预测视频很清晰，为何仍会撞杯子？视觉相似性不一定衡量接触动态、动作因果、空间精度和实时反馈。
