# 从 Embodied-AI-Guide 理解具身智能

本篇保留为全景速览。偏算法学习请在读完本篇后，以 10 算法图解详解作为主教材；那里展开训练目标、动作表示、推理机制、公式、伪代码与常见疑问。仓库各节的覆盖位置见 11 覆盖核对。

目标：理解原理、数据流与必要伪代码。依据仓库 README 与 algorithm、infrastructure、control、hardware 四篇内容重新组织。下面的教学例子和伪代码由导读补充。

## 1. 用一个杯子理解整个领域

任务：“把桌上的红杯子放进水槽。”语言模型可以描述步骤，但机器人还要知道杯子在哪里、怎样抓住它、手臂如何运动、杯子是否滑落，以及执行失败后怎么办。它改变真实世界，而真实世界不会因为文字上写着“已抓住”就真的完成抓取。

具身智能的核心是交互闭环：传感器获得观测，系统根据目标选择动作，执行器施加动作，世界产生变化，再重新观测。身体决定它能观察什么、能执行什么，以及错误有什么代价。轮式机器人不能直接使用双臂机器人的动作空间，柔软物体也不能完全按照刚体假设处理。

![图1 算法控制闭环](图解/01_算法闭环.png)

读图：观测经过表征与策略产生动作，执行后的世界成为下一次输入。训练损失只评价局部拟合，完整闭环还需要任务评测。

一个简化系统可以写成：

```text
目标 g：把红杯子放到水槽
观测 o：相机图像 + 关节角 + 夹爪状态
策略 π：根据观测和目标提出动作
控制器：将动作转换为可执行的关节运动
环境：机器人和物体实际发生变化
反馈：检查杯子是否被抓住、是否到达目标
```

这里的观测 observation 不等于真实状态 state。杯子背面的把手可能被遮住，杯子是否装水可能无法从一张图片确定，传感器也有噪声。论文如果使用机器人看不到的仿真真值训练或评估，要注意这些信息在部署时是否仍然可用。

## 2. 仓库的四张地图

算法篇回答如何理解世界、学习动作和做决策。基础设施篇回答如何产生数据、搭建环境、比较方法。控制篇回答怎样把目标变成稳定、受约束的实际运动。硬件篇回答机器人能感受到什么、能施加什么，以及数据怎么采集。

这四部分互相制约。相机标定错了，换一个更大的动作模型可能仍然抓偏；数据只有成功演示，机器人可能不知道滑落后的恢复动作；仿真中的物体摩擦过于理想，模型在真机上会失败。具身系统的性能不能只用网络架构解释。

## 3. 机器人到底看到了什么

RGB 图像提供颜色、纹理、类别信息；深度图或点云提供空间结构；关节角、速度、夹爪开合等本体感知 proprioception 告诉系统身体状态；力觉和触觉帮助判断接触、滑动和抓握是否稳定。不同传感器解决不同不确定性。

仓库列出的视觉模型可以按功能理解：CLIP / SigLIP 提供图文语义关联；DINO 提供可迁移视觉表征；Grounding DINO 根据文字定位物体；SAM 系列根据相应提示做分割；FoundationPose 用于物体位姿估计。它们的输出可能是特征、框、掩码或位姿，不会自动变成可执行抓取动作。

比如先用“red cup”找到框，再分割杯子，结合深度得到空间点，最后设计抓取位姿。每一步都可能错：找到了红碗、深度缺失、杯子掩码包含桌面、抓取位姿撞到把手。因此检查每个中间输出很有价值。

仓库对单目深度的提醒可以理解为尺度问题：相对深度不能直接当成米使用。具体模型可能有 metric depth 版本或尺度恢复能力，应核对实际权重与输出约定；不能把所有单目深度模型一概视为没有绝对尺度。

## 4. 坐标系、FK 和 IK：策略输出怎样落到机器人上

相机说“杯子在右侧”，机械臂需要的是基座坐标系中的目标。手眼标定得到二者的坐标变换。一个点可以示意为：`p_base = T_base_camera × p_camera`。T 包含旋转与平移；实际计算使用齐次坐标，并必须明确单位、轴方向和变换方向。

FK（Forward Kinematics，正运动学）根据关节角求末端位姿。IK（Inverse Kinematics，逆运动学）根据希望的末端位姿求关节角。IK 可能没有解，也可能有多个解；有解不等于运动路径没有碰撞。

位姿 pose 包含位置与朝向。把杯子移到同一个三维位置，夹爪朝向不同，结果可能完全不同。自由度 DoF 表示独立运动变量的数量，不能简单理解为“自由度越多越好”，因为控制与数据复杂度也随之增加。

第一阶段不要求推导完整动力学，只需理解：感知提供目标、运动学处理几何、规划考虑路径、控制器跟踪轨迹。它们与学习策略可以组合。

## 5. 一条机器人数据是什么

一条 demonstration / trajectory 是一次任务的时间序列，例如：

```text
episode：抓红杯子
t=0：图像、关节角、夹爪状态、专家动作
t=1：执行后图像、身体状态、下一动作
...
t=T：终止标志、成功标签、必要元数据
```

语言指令、机器人本体、相机位置、时间戳、动作单位、控制模式都可能是重要元数据。只保存视频，通常无法知道每一帧对应的机器人指令；只保存关节指令，也可能缺少环境反馈。

常见动作有三类：关节位置 / 增量、末端位姿 / 增量、速度或力矩。比如同一个六维数字可能表示末端 xyz 加旋转，也可能根本属于关节空间，必须看定义。绝对坐标与相对增量混用会使动作失效。

时间同步尤其重要。图像是抓取前的一帧，而标签动作已经是抬起后的指令，模型就会学到错配关系。训练之前理解数据语义，比直接改模型更有收益。

## 6. 模仿学习：从演示学会动作

BC（Behavior Cloning，行为克隆）把专家动作作为监督标签，学习观测到动作的映射。它与分类或回归训练的思路类似，只是输出变成机器人动作。

```text
for batch in 演示数据:
    观测, 目标, 专家动作 = batch
    预测动作 = 策略(观测, 目标)
    损失 = 预测动作与专家动作的差异
    更新策略参数，降低损失
```

示意目标为 `L_BC = E[distance(π(o,g), a_expert)]`。distance 取什么形式，取决于动作表示与策略类型；生成式策略不一定使用简单均方误差。

它的主要问题是 distribution shift：模型稍微抓偏，进入专家演示中很少出现的状态；这时又更容易预测错。演示全是“已经抓住后抬起”，模型可能不知道抓空后应该重新对齐。

如果同一场景允许从左抓或从右抓，直接把两种专家动作取平均可能得到一个碰撞路径。这解释了为什么动作分布的多模态表达很重要，而不仅是网络更大。

## 7. ACT：为什么一次预测一段动作

![图4 ACT训练与部署](图解/04_ACT训练推理.png)

读图：训练中的后验编码器可以读取专家未来动作，但部署没有这些标签。原始实现常用先验中心 z=0；它是潜变量设定，不是关节置零。完整损失与融合机制见 10 第 5 节。

ACT（Action Chunking with Transformers）预测未来一段动作，借助条件变分自编码器（CVAE）建模演示行为的变化，并用 Transformer 将观测映射为动作序列。动作分块有助于表达连贯操作，也减轻逐步决策的部分问题。

想象“伸手、合爪、抬起”是连贯短动作。每步独立预测，可能一会儿向左、一会儿向右。一次生成一段动作能利用序列结构。但预测十步并不意味着无反馈地执行十步一定更好；执行多少步后重观测，是部署设计的一部分。

ACT 还可对不同时间预测的、对应同一执行时刻的动作进行 temporal ensembling，以平滑执行。论文实现还包含潜变量、KL 正则等细节，完整输入、动作块、潜变量、损失和部署区别见 10 第 5 节。

```text
循环直到结束:
    读取最新图像和关节状态
    动作块 = ACT(当前观测)
    根据部署策略，执行部分动作或融合重叠预测
    重新观测，更新后续预测
```

这是教学伪代码，不是官方可直接运行的 ACT 实现。

## 8. Diffusion Policy：从噪声形成合理动作序列

![图7 扩散部署](图解/07_扩散推理.png)

读图：生成器内部的多次去噪共同产生一个动作块，机械臂随后执行其中一部分。去噪步与交互时刻不同，训练的随机噪声监督见 10 第 6 节。

扩散策略学习给定观测时动作序列的分布。训练时给专家动作加噪声，网络学习去噪；推理时从噪声开始，逐步得到符合观测与任务的动作序列。

```text
训练：专家动作块 → 加噪 → 预测噪声 / 去噪方向 → 更新模型
推理：随机动作噪声 → 条件去噪多步 → 动作块 → 执行前几步
```

它能更自然地保留多个可行行为模式。代价是迭代生成带来计算延迟，且动作的合理性仍受数据和观测约束。DP3 加入点云表示，强调空间信息对动作学习的作用。不要把“扩散生成的视频”和“扩散生成的动作”混在一起：生成对象不同，训练目标也不同。

## 9. RL：根据交互结果改进策略

RL（Reinforcement Learning，强化学习）让策略通过交互获得奖励，并优化长期回报。示意目标是 `J(π) = E[Σ γ^t r_t]`。r 是反馈，γ 控制未来奖励的权重，不需要现在推导求导过程。

```text
重复:
    策略在环境中执行，收集状态、动作、奖励与终止信息
    根据轨迹评估哪些行为产生更高长期回报
    更新策略 / 价值函数
    在独立评测环境检查实际任务表现
```

操作任务的奖励可能难设计：距离杯子更近，不等于成功抓取；抬起夹爪，不等于杯子被拿起来。奖励写错，模型可能学到“看起来高分”的行为。仿真中的并行试错有助于训练，但现实交互成本、任务重置和安全约束不能忽略。

仓库将 IL 更常用于操作、RL 更常用于运动控制作为入门经验。这是常见模式，不是严格边界；操作同样使用 RL，运动同样使用演示和动作先验。IL 预训练后进行 RL 后训练，是值得认识的组合路线。

## 10. VLA、大模型规划和快慢系统

VLA（Vision-Language-Action）把视觉、语言和动作连接起来。常见输入是图像、语言任务和机器人状态，输出是动作或动作块。语言提供任务条件，视觉提供环境信息，动作头必须输出机器人能够解释的控制表示。

两种典型设计可以放在一起比较：一种由高层 LLM 分解任务，调用抓取、移动等技能；另一种由 VLA 直接根据观测和语言生成低层动作。实际系统可以分层组合：慢速语义规划决定子任务，快速策略与控制器负责执行。

“慢 / 快”是频率和职责的区别，不代表固定网络名称。具体控制频率取决于机器人、接口和算法。不能把大模型的一次文本响应直接等价为高频闭环控制。

语言知识能帮助认出“杯子”和理解“放进水槽”，但不能自动提供精确摩擦系数、接触力或可靠碰撞约束。语义理解与物理执行之间仍有距离。

## 11. 世界模型：预测我这样做会发生什么

策略回答“做什么动作”，世界模型回答“做了之后世界可能怎样变化”。一个示意关系为 `下一状态 ≈ world_model(当前状态, 动作)`。它可帮助规划、生成训练经验或评估候选动作。

```text
当前状态 = 编码(最新观测)
候选动作序列 = 产生若干方案
for 方案 in 候选动作序列:
    预测未来 = 世界模型展开(当前状态, 方案)
    分数 = 目标达成程度 - 风险 - 成本
执行最高分方案的第一步
重新观测，再次规划
```

这是基于模型的滚动规划示意。它不能保证安全：预测模型可能误判接触、漏掉障碍或低估不确定性。一般视频生成器如果没有可靠动作条件，不能仅凭画面逼真就视为可控物理模拟器。详细比较见 P4 导读。

## 12. 仿真、数据集与基准各自是什么

Simulator 是可以交互的环境，负责执行动作并产生新状态与观测；Dataset 是已经记录下来的经验；Benchmark 是任务、评分、数据划分、重置方式和预算等评测协议。三者经常配套，但作用不同。

Sim2Real Gap 包括视觉、动力学、摩擦、接触、延迟和噪声的差异。Domain Randomization 在训练时变化这些条件，帮助策略避免只适应一个狭窄环境。但随机化范围不合理，可能增加训练难度，或仍覆盖不到真实问题。Real2Sim 则从真实物体和场景构建仿真表示。

训练时随机杯子颜色，测试时换杯子形状，二者检验的泛化不同。评测需要说清未见的是对象、位置、场景、任务组合还是机器人本体。

## 13. 用 RoboTwin 理解完整生命周期

仓库以 RoboTwin 2.0 和 ACT 为实践主线。你现在可以先理解五步：认识任务与仿真；理解轨迹内容；把数据转换成策略输入；训练；在独立环境执行并分析失败。

仓库快照的策略工程通过 XPolicyLab 管理，安装与调用路径可能随版本更新。它提醒使用对应的图像解码工具、对齐 bench / checkpoint / action_type 等配置，这说明“同样叫 ACT”并不保证数据语义和部署接口一致。

你可以暂时不安装环境，先读一条轨迹的字段说明，画出：原始记录 → 图像解码与动作归一化 → 模型输入 → 预测动作 → 反归一化 → 控制接口。知道每一个箭头做什么，就已经实现当前的理解目标。

如果以后开始实践，第一轮只选一个任务和一个基线。先确认数据能显示、动作单位正确、评测能记录失败，再考虑换成大型 VLA。仓库中的显存、成功率与榜单信息是特定快照下的指引，实际执行时核对官方版本。

## 14. 怎样看成功率而不被数字误导

成功率 80% 至少还需要任务集合、试验次数、训练测试划分、重试预算和成功判断方式。模型 A 在简单位置测试、模型 B 在随机遮挡测试，数字不能直接比较。

可以把失败标为：感知错误、坐标 / 标定错误、动作生成错误、轨迹碰撞、抓握滑落、任务进度丢失、终止判断错误。先分类再选改进方法，避免所有问题都归结为“模型不够强”。

长任务还要统计完成子任务数量、恢复成功率、总耗时、干预次数与代价。只报告最终成功会隐藏改进来自什么模块。

## 15. 入门自测与参考答案

1. 图像中杯子位置正确，机械臂却总固定偏 2 厘米，应先查什么？先检查坐标变换、标定、单位和时间同步，再判断模型问题。
2. BC 训练误差很低，执行却经常失败，为什么？离线误差只衡量演示分布；闭环执行可能进入陌生状态，并累积误差。
3. 预测未来画面很漂亮，为什么抓取不一定更好？图像质量可能没有反映接触、碰撞、动作因果和精确几何。
4. 控制器与 VLA 有什么区别？VLA 生成任务条件下的动作意图 / 指令；控制器将其在机器人动力学和约束下跟踪执行，具体边界取决于接口。
5. 新人应该先背所有模型名吗？先建立输入输出与问题分类，再记少量代表作；理解比名称覆盖更重要。
