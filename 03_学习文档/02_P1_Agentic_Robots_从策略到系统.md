# P1：从动作策略到 Agentic Robots

原文：Towards Agentic Robots: Model, Data, Environment, and Harness。Chonghan Qin 等，arXiv:2610.20442v1，2026-10-14，79 页。此版本为预印本。[公开记录](https://arxiv.org/abs/2610.20442)。

## 1. 先抓住主张

![图1 策略在系统中的位置](图解/01_算法闭环.png)

读图：动作策略只是中间一环。P1 的 Model、Data、Environment、Harness 分别涉及可学习能力、经验来源、交互条件与运行组织。较强动作模型仍需要进度、反馈和失败处理；训练目标与执行闭环的区别见算法详解第 1、13 节。

一个动作预测模型再强，也不自动具备长期任务管理、失败恢复、数据采集和能力改进。本文用 Agentic Robots 讨论这些功能如何共同构成机器人系统，并以 Model、Data、Environment、Harness 四个领域组织研究。

这里的 agentic 强调系统能够围绕目标作决策、使用反馈调整操作和组织能力。不能简单理解为“把 LLM 接在机器人上”，也不能仅凭模型名字判断系统是否有这些能力。

## 2. 四种范式如何连接

| 范式 | 主要回答 | 杯子例子 | 单独使用时的典型缺口 |
|---|---|---|---|
| 任务策略 Policy | 根据观测做什么动作？ | 当前画面对应怎样的抓取动作？ | 陌生任务、持续进度管理 |
| VLA | 如何将视觉与语言知识连接到动作？ | 理解“红杯子”并执行操作 | 语义理解不等于长期可靠执行 |
| WM / WAM | 哪些未来值得预测，预测怎样帮助动作？ | 抬起后是否会碰到旁边物体？ | 预测误差与控制接口问题 |
| Agentic Robot | 如何组织执行、反馈与改进？ | 抓空后诊断、换方案、记录经验 | 系统成本、归因、真实部署可靠性 |

作者明确把它们视作可共存的研究传统与能力。不要把这张图理解为新范式出现后，旧策略或控制器就失去价值。

## 3. 四领域、十七类：记问题而不是背名单

Model 有五类：Training、Perception、Planning、Robot Control、Adaptation。它研究应该学什么、理解什么、决定什么和控制什么。比如抓取失败是策略缺少演示，还是高层计划选择了错误对象？

Data 有三类：Collection、Annotation、Refinement。它研究采什么数据、如何标注、如何筛选和改善数据。比如对失败场景补采演示，或识别动作与视频错位的轨迹。

Environment 有三类：Reconstruction、Task Generation、Benchmarking。它研究构造什么世界、任务和测试。比如生成带遮挡的杯子场景，检验策略能否处理困难位置。

Harness 有六类：Orchestration、Memory、Monitoring and Recovery、Skills、Infrastructure、Layered Systems。它研究如何组织可执行能力、记住状态、检测问题、恢复执行与支持长期使用。

四领域是组织研究的视角，并不是四个互不相交的软件包。生成任务会改变数据分布，数据改变策略，策略失败又指导下一轮任务生成。

## 4. Harness 为什么值得单独研究

Harness 可译为运行支撑框架。它决定模型什么时候被调用、获得哪些观测、能用哪些工具、结果怎样验证、失败怎样处理、哪些状态保留到下一步。

假设机器人抓空了。基础策略可能继续执行抬起动作。加入监测后，系统发现“夹爪闭合但杯子仍在桌面”；加入恢复机制后，它重新定位杯子、调整抓取位置。真正的改善来自闭环证据，而非多写一句“请认真完成任务”。

监测也不能只依赖模型自述。应优先用适当的视觉、触觉、夹爪或环境状态证据。例如仿真中可直接读取物体位姿，真机中则需传感器推断；这两种成功判断的可靠性不同。

## 5. 教学伪代码：可靠执行一个多步骤任务

```text
任务 = 解析用户目标
计划 = 根据观测与可用技能生成子任务
记忆 = 保存目标、已完成步骤、已知约束

while 尚未达到最终目标:
    观测 = 读取环境与机器人状态
    下一技能 = 根据计划、记忆和观测选择
    检查技能的前置条件
    执行下一技能
    结果 = 根据新观测检查实际后果
    if 成功:
        更新完成状态与证据
    else:
        诊断失败原因
        在预算与执行约束内恢复 / 重新规划
    达到预算或无法恢复时，明确记录未完成状态

最终用环境证据验证目标
```

这是导读补充的抽象循环。具体系统可能使用状态机、行为树、LLM 工具调用、VLA 或混合实现。论文中的 Monitoring and Recovery 与 Orchestration 是查找对应方法的入口。

## 6. 和另外四篇论文的关系

世界模型论文展开 Model 中预测与表征的分支。长时程综述解释 Harness 如何维持跨步骤与跨上下文的一致性。两篇 RSI 论文解释执行反馈怎样变成长期能力更新，以及改进规则自身是否发生变化。

Agentic 执行与 self-improvement 不等价。系统可以在一次任务内不断重新规划，但任务结束后不留下任何能力变化。反过来，一个固定训练流程可能持续更新策略，却没有自主规划与恢复能力。

## 7. 作者主张、证据与尚未解决的问题

本文的直接贡献是分类、比较与研究议程，不能当作一个已经解决通用机器人问题的实验系统。它讨论的重点包括公平评测、真机部署效率和跨本体泛化。

阅读具体系统案例时，至少记录基础模型、底层执行器、观测权限、重试次数、推理延迟和任务集合。成功率变化可能来自这些因素中的任何一个。即使原文给出模型或榜单比较，也不能脱离其协议外推到其他机器人。

## 9. 一个适合初学者的小实验

冻结相同动作策略，在相同任务和种子上比较：固定步骤执行、加成功检查、加成功检查与恢复。报告最终成功率、检测误报 / 漏报、恢复成功率、平均耗时和调用次数。

必须固定策略与观测条件，否则无法知道改善来自 Harness 还是更强的底层模型。该实验是学习建议，不是本文作者的实验或成熟选题结论。

## 10. 自测

为什么抓取策略很强，收拾整张桌子仍然可能失败？因为任务组织、已完成状态、异常恢复与终止判断也会影响最终结果。

系统多重试了三次，成功率提升，能否说明架构更好？需要计入重试与计算预算，并比较同等预算下的结果。

你应能画出：任务 → Harness → 策略 / 技能 → 控制器 → 环境 → 反馈 → Harness 的闭环。
