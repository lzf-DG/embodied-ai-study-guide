# P3：长时程 Agent 为什么难

原文：Towards Long-Horizon Agents: A Survey，副标题 Foundation, Evolution, Harness, Optimization, Application, and Frontier。Guanting Dong 等，本次桌面 PDF 共 149 页。[作者资源仓库](https://github.com/RUC-NLPIR/Awesome-Long-Horizon-Agents)。版本识别以随包原文为准，此处不额外推断未核对的发表状态或 arXiv 编号。

## 1. Long-Horizon 不只是运行很久

![图17 长期任务的验证与恢复](图解/17_长任务恢复.png)

读图：计划中的下一项依赖环境事实被验证。命令已发送不能当作任务已完成；恢复需要知道哪里失败，记忆要记录证据与进度。动作块预测未来，历史记忆总结过去，二者作用不同。

一次搜索等待五分钟，可能没有复杂依赖；两分钟内完成多个互相制约的机器人操作，却可能是困难的长时程任务。本文强调大量耦合的逻辑依赖、持续交互和反馈修正。

它将能力看作 Externalized Harness Engineering 与 Internalized Model Optimization 的共同结果。前者把记忆、工具、工作流和验证放在系统外部；后者通过数据、训练和经验将相应能力内化到策略中。

更多上下文有帮助，但上下文容量不是长期任务能力的充分条件。模型仍可能忽略关键约束、错误总结、目标漂移或在中途提前宣布完成。

## 2. 从“收拾一个杯子”到“收拾一间厨房”

厨房任务需要先识别物体、腾出空间、处理杯子、清理台面、确认没有遗漏。杯子还可能装水，垃圾桶可能已经满了。一开始的计划并不包含所有情况，系统必须依据新观测更新决定。

已完成子任务不能反复重做，未完成步骤不能在总结中消失，失败也可能破坏后续前置条件。长期任务要求维护状态与依赖，而不仅是一次生成更长的步骤列表。

## 3. 模型与 Harness 的耦合

作者示意 `Agent = π_θ ⊕ H`。π 是基础策略，H 是运行支撑框架，⊕ 表示运行时耦合，而不是数字相加。

```text
Harness 汇总：任务 + 历史 + 当前观测 + 检索记忆 + 工具结果
模型根据汇总内容提出下一动作
Harness 检查并执行动作
环境产生变化与反馈
Harness 更新持久状态和工作上下文
继续调用模型
```

模型看到的上下文通常只是历史的有损摘要，环境观测本身也不完整。因此作者借助 POMDP（Partially Observable Markov Decision Process）描述部分可观测的决策条件。第一遍只需懂“世界真状态和系统知道的状态不同”。

## 4. 三层任务与能力

H1 / C1 对应单个工作上下文内的多步推理与执行。比如在一次连续会话内完成几个互相依赖的操作。

H2 / C2 对应跨上下文的连续任务与记忆。比如任务执行很久，需要换工作窗口或跨会话继续，却要保留当前阶段、未完成事项和约束。

H3 / C3 对应跨任务经验积累与使用。比如多次收拾厨房后，系统在新的相关任务中调用过去经验证的经验。

这是作者用上下文边界刻画依赖负担的分类。不是按分钟数划分，也不能直接映射成两篇 RSI 的 L1–L5。

## 5. 三类典型失败

Goal Drift 与 Compounding Error：目标逐渐偏移，局部错误改变后续轨迹。机器人原本要把杯子收进水槽，中途却把“移走杯子”当成完成。

Context Rot 与 Context-Limit Pressure：信息变多后模型检索和使用关键事实的能力下降；摘要又可能删掉尚未解决的限制。某些系统会因感知到上下文压力而过早停止。

Sparse / Delayed Rewards 与 Irreversibility：最后才知道任务失败，难确定哪一步导致；现实动作还可能无法撤销。软件回滚与物理恢复的意义不同。

## 6. 为什么单步准确率高仍不够

教学计算：如果每步成功概率都是 0.98，且各步独立、任何失败都会导致全任务失败，那么 50 步全成功概率为 `0.98^50 ≈ 0.364`。这只是说明性模型；真实步骤并不独立，也可能恢复、重试或共享误差。

它提醒我们优化最终轨迹，而非仅看下一动作准确率。检测错误、修复前置条件、检查目标是否真正完成，都可能改变全任务成功率。

## 7. 外部 Harness 的六类能力

Loops and Workflows 让系统按照执行结构推进任务；Context and Memory 决定当前该看什么、什么跨阶段保留；Tools、MCP and Skills 提供可执行接口和复用能力；Orchestration 组织角色与协作；Hooks and Middleware 在执行前后插入检查；Verification 评估动作、阶段或最终结果。

工作流可以线性、分支、计划执行交替。结构越复杂不一定越好，额外协调会增加成本与新的失败路径。对一个简单任务，明确的状态机可能比复杂多 Agent 编排更可靠。

技能不是“一个名字”。它需要输入、适用条件、前置条件、执行过程和结果检查。`pick(cup)` 若没有明确坐标约定和成功判断，复用会产生歧义。

## 8. 记忆应该保留什么

短期工作上下文用于当前决策；持久记忆用于跨窗口或跨任务保留可用信息。二者不能只靠把所有历史塞进去实现。

```text
阶段检查点：
    原目标与约束
    已完成步骤及其证据
    尚未完成步骤
    物体 / 工具当前状态
    失败尝试和原因
    接下来需要验证的事实
```

这份模板由导读补充。关键是区分事实、推测和过期信息。昨天记录“杯子在右边”，今天桌子已被重新布置，检索到这段记忆可能反而有害。

评价记忆至少看写入是否正确、检索是否相关、执行时是否使用、最终是否有收益。更多记忆条目不等于更多可靠能力。

## 9. 内部优化怎样配合外部系统

本文组织的内部优化涵盖架构、数据与环境生成、预训练 / 中期训练、微调、Agent RL、On-Policy Distillation 和 Self-Evolution。第一遍只需理解训练改变策略能力，Harness 改变运行条件，两者需要匹配。

在一种工具接口上训练的策略，换了工具返回格式可能失败；训练时有完整历史，部署只给短摘要，也会产生分布变化。外部机制能够先提供支撑，之后再通过训练内化部分行为，但这不是自动发生的过程。

Credit Assignment 指长轨迹中如何判断哪些决策对最终结果有贡献。中间验证能提供更密反馈，但不可靠的验证器也会引导错误学习。

## 10. METR 时间趋势要谨慎读

文中引用前沿 Agent 的任务时间跨度趋势。相关时间跨度常用人类完成任务所需时间和某个成功概率阈值定义，且主要来自特定软件或类似任务分布。

它不等于模型能以同样成功率无人干预控制真实机器人多久，也不等于任务平均运行时间。读取曲线时看任务集合、成功阈值、模型与 Harness 设置，以及不确定性。

## 11. 第一遍阅读建议

先读第 4–14 页的动机、定义、H1–H3 和邻近概念；第 20–36 页重点读记忆、工作流和验证；第 37–55 页先看优化分类，暂跳过大量方法名；第 55–66 页按兴趣看应用与评测；再看第 67–74 页的前沿与结论。第 75 页以后的大量文献主要供后续检索。

本文五类应用包含软件工程、信息搜索、计算机使用、多模态和通用 Agent。具身机器人是需要结合物理反馈重新验证的迁移方向，不能直接从其中的软件成功率得出真机能力结论。

## 12. 小实验与自测

用固定底层策略完成一个多步骤仿真任务，比较无检查点、结构化检查点、检查点加恢复三种条件。控制任务种子、计算预算与观测权限，记录最终成功、遗漏步骤、重复执行、恢复成本和记忆错误。

你应能解释：为什么长上下文仍可能丢目标？为什么总结会产生新的错误？怎样判断终止是真正完成而非预算耗尽？怎样证明记忆产生了收益而非只是增加模型调用？
