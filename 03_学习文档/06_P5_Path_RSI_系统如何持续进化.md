# P5：把整个 Agent 系统作为改进对象

原文：The Path to Recursive Self-Improving Agents: Foundation, Framework, and Future Directions。Shuaiqi Liu 等，桌面文件共 70 页。公开记录为 Preprints.org，2026-08-03，DOI: 10.20944/preprints202608.0051.v1。[论文记录](https://doi.org/10.20944/preprints202608.0051.v1)。此记录是预印本，页面上的 Review 是文章类型，不等于已完成同行评审。

## 1. 先掌握五个组件

![图19 改进的对象](图解/19_递归改进.png)

读图：新数据更新策略只是持久学习；如果负责采样、优化或验证的机制也被修改并继承，才需要进一步讨论递归。不能只看到循环箭头就判断系统已达到有效递归。

本文把系统状态写为 `x_t = (M_t, H_t, D_t, T_t, Imp_t)`。与只盯着模型权重相比，它把数据、运行框架、训练器和改进机制一起放入分析。

| 组件 | 作用 | 机器人教学例子 |
|---|---|---|
| M：Foundation Model | 提供参数化的理解、决策或动作能力 | 基础模型或动作策略 |
| H：Agent Harness | 组织上下文、工具、技能和执行 | 调用抓取技能、记录进度、检查结果 |
| D：Agent Data System | 将轨迹和反馈变成训练 / 评价资料 | 收集失败、筛选轨迹、生成课程 |
| T：Agent Trainer | 将数据与学习信号变成持久参数更新 | BC、RL 或其他优化流程 |
| Imp：Improvement Mechanism | 决定诊断、提出、验证和整合什么修改 | 判定瓶颈并选择数据、框架或训练改动 |

Imp 是“改进过程的决策与规则”，不能简单等同于优化器。T 中某个训练算法可能被 Imp 修改，但两者的职责不同。

## 2. 为什么组件必须一起看

假设图像归一化改变了，模型仍按旧分布解释视觉输入；或 Harness 改了动作单位，控制接口没有更新。局部组件看起来更好，整个系统却可能更差。

另一个例子：补充了更多抓取演示，机器人仍抓偏，真正问题是相机到基座的变换错误。若改进机制只允许训练模型，无法解决这个瓶颈。

因此本文不仅关心更新哪个组件，也关心组件的依赖、接口一致性和系统层面的结果。

## 3. 四阶段循环

Diagnose：根据端到端表现、模块状态、接口和反馈定位瓶颈。

Propose：提出一个或多个候选修改，明确目标组件与具体变化。

Evaluate：检查性能、成本、兼容性和适用条件，筛选候选。

Integrate：将通过验证的修改整合为新版本，并保证后续仍可使用。

```text
证据 = 当前系统的轨迹、结果、接口检查与预算记录
瓶颈 = Diagnose(x_t, 证据)
候选 = Propose(x_t, 瓶颈)
对候选进行隔离评估、回归检查和独立检验
接受的修改 → Integrate → x_(t+1)
保留修改依据、版本与使用条件
```

这段代码是教学示意。真实系统并不保证每轮都提升；回归、拒绝和无效更新都是改进研究需要报告的结果。

## 4. 本文 L1–L5 的标准

| 层级 | 本文名称 | 必须理解的区别 |
|---|---|---|
| L1 | Manual Improvement | 系统修改来自外部人工开发与部署 |
| L2 | Assisted Improvement | 系统提供建议 / 诊断，人负责实质验证与应用 |
| L3 | Programmatic Self-Improvement | 系统自主提出、应用、验证组件修改，Imp 固定或外部维护 |
| L4 | Bounded Recursive Self-Improvement | 连 Imp 也能作功能性修改，并在受限领域长期使用 |
| L5 | General Recursive Self-Improvement | 改进机制的能力可跨广泛且变化的领域有效迁移 |

“功能性修改”意味着影响后续改进过程，不能仅仅改注释或文件名。L5 的 generality 指递归改进能力的跨领域通用性，不只是当前策略能完成很多任务。

## 5. 与 P2 分级为什么不能混用

P2 围绕自主权范围展开：执行、策略、经验、环境适应、元改进。P5 围绕人工介入、组件自主更新、Imp 是否可改及跨领域迁移划分。两者回答的问题相近，但坐标不同。

例如 P2 的 L1 强调自主执行既定更新；P5 的 L1 却是人工改进。P2 的 L5 强调元改进；P5 的 L4 已要求受限领域内修改 Imp，L5 更进一步要求跨领域的递归改进泛化。

所以记录文献时应写“P2-L3”或“P5-L3”，并附定义。无法仅靠编号给一个实际系统自动定级。

## 6. Harness 可以在不改权重时进化

本文把记忆、技能 / 工具、提示 / 上下文、编排 / 架构和自引用代码修改放入 Harness 自我改进研究。改变这些组件也可能改变能力，不必每次重新训练基础模型。

例如机器人把经验证的恢复策略写入技能库，后续遇到相同失败便能调用。若技能写错、检索错或使用条件变化，它又可能导致退化。持久记录必须有来源、适用条件和结果证据。

“保存更多经验”与“形成更可靠的可复用知识”是两件事。阅读记忆方法时，不只看条目数量，也看写入、检索、调用和任务收益。

## 7. 数据与训练器也能成为改进对象

D 连接运行中的轨迹与后续学习。它可以包含环境生成、任务生成、课程、轨迹筛选与评价证据。数据产生和数据利用需要共同设计：收集大量相似简单轨迹，可能不能弥补困难状态的缺口。

T 将数据与反馈转换成更新。修改监督信号、奖励、优化策略、训练基础设施会改变训练结果，但仍需看谁作决定，以及 Imp 是否固定。

传统固定配方下的持续训练可归为程序化自我改进的一种情况。它具有价值，但没有因此自动获得“改进改进机制”的能力。

## 8. 真正的递归在哪里

普通循环：`Imp_fixed` 每轮根据相同规则更新 M 或 H。递归循环：Imp 自己也是状态的一部分，系统可以提出 `Imp_new`，通过验证后让后续轮次使用新的改进方式。

杯子教学例子：旧 Imp 见一次失败就增加一条技能。新 Imp 先判断失败是否可重复、是不是标定问题，再决定改技能还是修接口，并要求在未参与生成的任务上验证。改变的是以后更新的决策规则。

然而把这个过程写进代码不等于已经证明它有效。必须检验新规则在新任务、多个轮次和相同总预算下是否改进可靠性或效率。

## 9. 怎样评价“持续进化”

至少分开观察当前任务得分、旧任务保留、更新被实际复用的比例、后继系统质量、总资源消耗，以及改进机制的迁移效果。

如果系统反复用同一测试集选择修改，测试集会逐渐变成优化目标。更好的分数可能来自适应测试集，而非一般改进能力。因此需区分开发评价与独立测试，并报告预算、失败、版本轨迹和停止条件。

复杂的多组件协同也需要归因：固定其他组件，只修改一个模块；再比较联合改动。否则不能说清收益来自哪里。

## 10. 第一遍阅读建议

先读第 1–3 页与图 1；第 5–9 页精读五组件、L1–L5 和四阶段过程，尤其第 7 页表 1。随后从第 3、4、5 节分别选 Harness、Data、Trainer 的一个分支，看第 6 节如何协同改进，最后读第 7 节开放问题。

第 4 页的大分类图和后面大量方法表适合检索，不需要第一遍记完。按“改什么、证据是什么、规则是否固定”整理三篇代表作即可。

## 11. 与具身选题的连接

较容易切入的方向是失败驱动的数据选择、技能与记忆更新、恢复机制、评估器一致性，而不是立即让机器人自主修改所有代码和训练方法。

选择一个固定策略和仿真任务，先搭建可记录、可比较的改进循环。明确任务分布、可修改组件和证据边界后，才讨论更高层递归。这样的研究起点更容易解释结果。

## 12. 自测

固定程序每晚自动训练一次新模型，属于真正 RSI 吗？仅凭这件事不能，需看 Imp 是否自主作功能性改变并被继承。

模型能做十类任务，说明 P5-L5 吗？不能，L5 需要改进能力在广泛变化领域中的有效迁移。

怎样判断更新有意义？看它是否触及真实瓶颈，在独立可比条件下产生收益，并被后续系统可靠使用。
